# Agent guide: Skimap.eu

This is the working agreement for AI agents in this repo. Cursor loads it automatically; Claude Code loads it through `CLAUDE.md`. Keep it true: when it is wrong or missing something, fix it in the same change (see [Learn](#learn)).

## What this is

A static map of Austrian ski resorts and the multi-resort season passes that cover them, with prices by age and purchase date, a trip planner, and 26 languages.

- Next.js 15 App Router with `output: "export"` (static files in `out/`), React 19, TypeScript, Zod.
- Maps: MapLibre GL with OpenFreeMap by default. Mapbox GL only with a token, storage consent, and budget (README, "Mapbox load budget").
- Hosting: Cloudflare Pages builds `main` for production and serves `out/` plus the Pages Functions in `functions/` (D1 databases). GitHub Pages mirrors the static site under `/ski-pass-map`.
- Everything personal (favourites, plan, birth year, location) stays in the visitor's `localStorage`.

## Where things are

| Path | What lives there |
| --- | --- |
| `src/app/` | Routes (`[lang]/…`), `DocumentShell.tsx` (html, head, CSP meta), `globals.css` (all styles; theme tokens on `:root`, dark mode under `prefers-color-scheme` and `[data-theme]`) |

| `functions/api/` | Cloudflare Pages Functions. Thin wrappers around `src/lib/**/handler.ts` |
| `data/*.json` | Generated by `npm run import:austria` from `imports/austria/`. Never hand-edit |
| `config/*.json` | Site name, base path, pass colours and labels, legal, affiliates |
| `scripts/` | Build helpers, importers, e2e runners, `check-lockfile.mjs` |
| `e2e/regression.spec.ts` | Playwright suite against `wrangler pages dev` |

## Commands

| Command | When |
| --- | --- |
| `npm ci` | Install. Do not use `npm install` just to install: it rewrites `package-lock.json` |
| `npm run dev` | Dev server at http://localhost:3000/ski-pass-map/ |
| `npm run lint`, `npm run typecheck`, `npm test` | After every change. About 10 seconds together |
| `npm run build` | Before finishing anything that touches app code, config, or data. Runs `validate`, `next build`, and the static checks |
| `npm run check:lockfile` | After any change to `package.json` or `package-lock.json` |
| `npm run validate` | After any change under `data/` or `config/` (the build runs it too) |
| `npm run test:e2e` | Map, navigation, or layout changes a unit test cannot cover. Builds an e2e variant and serves it locally with `wrangler pages dev`. Tests run in order and stop at the first failure; run one with `npm run test:e2e -- -g "part of its name"`. Needs Playwright Chromium. Takes minutes |

## How to work

Do these in order. Never skip Verify.

1. **Understand.** Restate the request in one sentence. Read the files you will touch and their tests. Run `git status` and `git log --oneline -5`: the owner may have work in progress, never overwrite it.
2. **Plan.** For anything bigger than a one-line fix, write a short numbered plan before editing: goal, files, risks, how you will verify. Use the todo list or Plan mode when the tool has one. Ask only when the choice belongs to the owner (product decisions, anything destructive or public). Otherwise pick the conventional option and say which one you picked.
3. **Build in small steps.** Put logic in `src/lib/` as pure functions with tests, and keep components thin. Match the code around you: names, short comments that say why, no new dependency without a reason.
4. **Verify.** Run lint, typecheck, and tests. Every bug fix and behaviour change gets a test; write the failing test first when you can. Run `npm run build` before you finish. For UI changes, run the app and look at it: desktop (1440×900) and phone (390×844), light and dark.
5. **Review your diff** (`git diff`) like a strict reviewer: correctness, edge cases (empty, null, offline, permission denied), privacy, keyboard and screen-reader use, all 26 languages, both map libraries, no leftover debug code.
6. **Commit** each finished, verified change locally in the house style below. Do not push, deploy, or touch remote resources unless the owner asked in this conversation.
7. **Learn.** Do the [Learn](#learn) step.
8. **Report** in plain language: what changed for the visitor, how you verified it, and anything left open or not verified.

In Cursor, a hook (`.cursor/hooks.json`) runs the step 4 checks each time you stop and sends any failure back to you. Fix the cause; never skip or weaken a check to get green. The hook also asks for the Learn step once per conversation.

Habits that save the most time:

- Read before you write. Search the code for an existing helper before adding one.
- Prove it, don't assume it: run the code, read the library source, check the data.
- Change only what the task needs. Note unrelated problems in your report instead of fixing them silently.
- After two failed attempts at the same thing, stop and re-plan from what you learned. After three, ask.
- Say plainly what you did not verify.

## Project rules

### Build and deploy

- Cloudflare Pages runs `npm clean-install` with its own npm (10.9.2) before the build command. A lockfile written by npm 11 can pass on your machine and on GitHub and still fail there. After any dependency or lockfile change, run `npm run check:lockfile`. If it fails, run the repair command it prints.
- The site is a static export: no request-time server code in `src/app`, no API routes, no image optimisation. Server code goes in `functions/`.
- Two targets: Cloudflare at the root path, GitHub Pages under `/ski-pass-map`. Build links with `langPath` / `pathWithLang` and `BASE_PATH`. Never hard-code the prefix.
- The CSP lives in `src/lib/security.ts` and `public/_headers`, and `src/lib/html.test.ts` keeps the two in sync. A new external host needs both.

### Text and languages

- Every UI string goes through `t("key")`. A new key goes into all 26 files in `src/i18n/messages/` with the same `{placeholders}`, or `src/i18n/messages.test.ts` fails. Write real translations, not English copies.
- UI text is plain: short sentences, no jargon, and it tells the visitor what to do next. An error message names the real cause (a timeout is not a block).

### Data

- To change `data/*.json`, change `imports/austria/*` or `src/lib/import-austria.ts`, then run `npm run import:austria` and `npm run validate`.
- Never invent a number (price, elevation, date). Missing is `null`, and the UI hides it.

### Map

- MapLibre and Mapbox differ. `fitBounds` padding: MapLibre adds the map's own padding and keeps it; Mapbox replaces it (see `src/lib/map-camera.ts`). Check camera changes against both.
- A style swap drops custom sources and layers. Re-add them on `style.load`, as `MapView.tsx` does.
- Mapbox GL drops a whole GeoJSON tile, circles included, when a label's glyph request fails. Every font in `labelFonts("mapbox")` must exist on Mapbox's font server, and test stubs answer font requests with 200.
- Renaming or replacing a layer, source, or CSS class: search `e2e/` for it and update the tests in the same change.

### Settings

- Save a setting only when the visitor changes it, and work out the default at runtime. A saved default wins over system preferences such as reduced motion on every later visit.

### Privacy and safety

- The device location is one point, replaced on each fix. Anything that deletes it (clear data, remove "My location", import) must stop the watch first.
- Never commit secrets or tokens (`.env.local` and `.dev.vars` are ignored). Never run a deploy, `wrangler … --remote`, or `git push` unless the owner asked; the shell hook asks the owner anyway.
- Keyboard and motion: every control is reachable with Tab and shows focus, Escape closes an overlay and returns focus, and animations stop under `prefers-reduced-motion`.

### Commit messages

- Subject: one plain sentence about what the visitor now sees or can do, for example "The language menu now floats above the page, and the bar stays in place while you move over it."
- Body: a short paragraph per area. Name anything the owner must do by hand.

## Learn

Goal: the same mistake never costs time twice. At the end of every task, answer three questions:

1. Did the owner correct me or reject something?
2. Did a check, build, or test fail for a reason this file does not cover yet?
3. Did I lose time finding something (a command, a file, a gotcha) that one line here would have saved?

If all three answers are no, change nothing. Otherwise edit this file in the same commit:

- Prefer fixing the section it belongs to (a command, a rule, a path) over adding a lesson.
- Otherwise add one line under Lessons: `- YYYY-MM-DD · area · rule. Why: what happened.` Make the rule specific and checkable ("run X after Y"), not a mood ("be careful").
- Search Lessons first and update a matching line instead of adding a second one. Keep at most 30 lessons. When full, merge related lines, or move a lesson that keeps coming up into the rules above.
- Delete a lesson the code has made obsolete. Never remove the sections above, and never weaken a safety rule unless the owner says so.
- When the owner corrects you, add the lesson right away, not at the end.

### Lessons

- 2026-09-29 · build · Install with `npm ci` and run `npm run check:lockfile` after any dependency change. Why: `npm install` on npm 11 dropped the `@emnapi/*` entries, and Cloudflare's npm 10.9.2 refused the lockfile, so production stopped building.
- 2026-09-29 · privacy · An action that deletes the device location must stop the location watch first. Why: "Clear all data" and removing "My location" left the watch running, and it saved the position again within 8 seconds.
- 2026-09-29 · a11y · A menu rendered in a portal moves focus into itself on open and back to its button on Escape. Why: the language list moved to the end of `<body>`, and Tab from its button never reached it.
- 2026-09-29 · e2e · When a component renders once per breakpoint, select the visible one (`:visible`) in Playwright. Why: two language switchers on the map page broke a strict locator in `e2e/regression.spec.ts`.
- 2026-09-29 · e2e · After map or UI changes, run `npm run test:e2e` to the end, not only unit tests. Why: five failures sat unnoticed for days: a removed layer still tested (`lift-chair`), missing test glyphs hiding every dot on Mapbox, a scroll-driven animation that never "finishes", a screenshot folder that exists only on Cursor's cloud machines, and the page-view rate limit tripping on a fast run.
- 2026-09-29 · a11y · Moving lifts follow `prefers-reduced-motion` until the visitor chooses (`storedLiftMotionChoice`). Why: the saved default "on" kept lifts moving for visitors who later asked for less motion.
